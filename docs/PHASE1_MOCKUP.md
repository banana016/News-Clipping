# Phase 1 — 목업 & 화면 설계

Phase 1은 코드 없이 이메일/브리핑 웹앱/카카오톡 3개 화면의 문구·동작을 확정하는
단계였습니다. 인터랙티브 목업 원본은 같은 폴더의 `phase1_mockup.html`을 브라우저로
열면 그대로 재현됩니다 (도움됨/별로예요를 눌러보면 카카오 발송 미리보기와 태그별
반영 비율이 실시간으로 바뀝니다 — 단, 이 목업의 데이터는 전부 가상이고 브라우저
로컬에만 저장됩니다).

## 확정된 3개 화면

### 1. 이메일 알림
- 발신: `브랜드 전략 브리핑 <brief@yourapp.app>` → 실제 구현은 Gmail SMTP로 대체
- 제목: `오늘의 마케팅·브랜드 전략 브리핑 — YYYY.MM.DD`
- 본문 상단에 `수집 N건 · 검토 N건 · 최종 선정 N건` 통계 한 줄
- CTA 버튼 하나 — "브리핑 페이지 열기" → 매직링크로 연결
- 발송 시각: 월·수·금 07:00 KST, 링크는 나만 아는 고유 매직링크

### 2. 브리핑 웹앱 (매직링크 페이지)
- 상단 통계 타일 3개(수집/검토/최종 선정) — 수집·검토는 눌러서 펼치는 참고용
  목록(수집은 점수 없음, 검토는 탈락 사유 배지 포함), 최종 선정만 전체 카드로 노출
- 최종 선정 카드: 태그 1~3개, 제목, 요약(핵심 내용) + 전략 해석, 원문 링크,
  도움됨/별로예요 버튼
- "카카오톡으로 보내기" 패널: 도움됨 표시한 기사가 있어야 활성화, 누르면 실제
  전송될 메시지 미리보기 표시
- "피드백 반영 현황" 패널: 태그별 누적 도움됨 비율을 막대(meter)로 표시 —
  이 비율이 다음 회차 가산점 자동 조정에 쓰인다는 것을 사용자에게 보여주는 용도
- 하단 안내: 기사 원문 전문은 저장하지 않고 제목·요약·링크·메타데이터만 보관,
  동일 이슈는 가장 구체적인 1건만 선정

### 3. 카카오톡 메시지 ("나와의 채팅")
- 도움됨 표시한 기사 전체가 메시지 1건으로 이어져 전송 (기사 여러 건을
  한 번에 트리거)
- 각 기사 앞에 인사이트 인용구(15자 내외, 예: "가격이 아니라 정체성을 바꾼다")를
  circled number(①②③)와 함께 배치
- 메시지가 카카오 길이 제한을 넘으면 **기사 사이 경계에서만** 다음 메시지로
  분리 — 기사 본문 중간에서 끊기지 않음
